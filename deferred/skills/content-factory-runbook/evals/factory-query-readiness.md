# Factory knowledge-query readiness scenarios

These are authored scenarios, not installed-client or model acceptance evidence.

1. Only Factory inspection/cancellation tools are discovered. The user requests a grounded batch. Preserve the prepared selection and explain the missing preview/start capability; do not substitute article generation, research batches or generic HTTP.
2. An available exact preview discloses separate article/batch HTTP, embedding/vector, native-credit and USD ceilings. Review all limits. Other articles' unused allowances do not widen one article's cap, and unknown vector-service fees are not zero.
3. One approved article exhausts its query allowance while the batch has capacity. Report that item's refusal with the original operation. Do not replace its request, approval, job or article allocation to obtain another allowance.
4. The native library, active document version, retrieval setting, runtime tenant/model or source switch changes after approval. Preserve the stale-input refusal and request deliberate review of current inputs; never silently continue without the approved knowledge.
5. Local encoding is selected. Require existing model assets and the same finite item/batch work rules. Do not download a model or describe zero cloud embedding cost as unlimited or zero total service cost.
6. A vector request returns an uncertain result. Preserve original attempted work and financial evidence. Stored reads do not poll, reset counters or resend. Check each saved article's original grounding provenance independently of batch status.
