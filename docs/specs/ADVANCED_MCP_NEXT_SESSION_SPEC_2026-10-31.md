## Implementation rules shared by all workstreams

1. Inspect existing adapters, native APIs, service owners and adjacent flows by concept and synonyms. Record what is reused or extended. Prefer the existing execution, approval, job, history and accounting seams. Introduce no parallel business store, orchestrator or provider client merely for MCP.
2. Before coding, freeze a finite capability table for A-D: existing tool or native operation, requested delta, R/W/P effects, role/scopes, owner, bounds, revision pins and acceptance cases. R means persisted reads with no writes; W means native persisted mutation; P means provider/paid execution. Composite operations must declare every effect. Reuse existing tool names wherever they already express the operation. New names are justified only by an uncovered native action.
3. Use closed schemas. Resolve organization, project, content group and section authority from server-owned relationships. Check both endpoints of link operations and exact workspace/content-group ownership. Organization membership alone does not authorize every project or section. Check authority again before worker execution and before publication of results.
4. Pin the approved source, body/revision, selection, plan, template, model, voice, target and execution inputs as applicable. Omitted and explicit-null optional fields must canonicalize consistently. Drift requires a new preview; it must not silently select current defaults or substitute another source.
5. Reuse browser approval and native business review as distinct requirements. Test the original approved preview through the real SDK, including quota refusal and stale/mismatched approval. Approval pages must not imply executable approval when native admission has already failed. Unknown cost remains unknown, never zero. Neither reinstalling the skill nor repeated approval is a server repair.
6. Reuse original operation IDs, queues, native credits, immutable provider allowances and receipts. Reads and polling cannot enqueue, spend, settle, provision or reconcile through an implicit write. Retries cannot mint another allowance, replace the original job or repeat an uncertain side effect. Expose partial, degraded and unknown outcomes with supported reconciliation actions and original receipts.
7. Keep feature flags, qualified execution profiles, credentials and entitlements authoritative. Resolve secrets through an existing secure server-side connection. Never put API keys, arbitrary actor IDs, raw credentials or unrestricted provider URLs into model-visible arguments. Missing engineering is unfinished work, not a fabricated credential or quality gate.
8. Enforce row/byte/token/source/provider limits before hydration or dispatch. Return bounded projections, progress, elapsed time, failed stages and concrete next actions. Do not expose raw corpora, private bodies, provider payloads or unsafe errors through a convenient status endpoint.
9. Keep authority-lock sessions short. Do not introduce organization/resource locks into a native worker session spanning the model graph. Earlier real PostgreSQL runs exposed nested organization-lock timeouts missed by SQLite; use the existing short-lived authority-check seam. Do not weaken locks or timeouts to make tests green.
