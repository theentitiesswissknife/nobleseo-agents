# Synthetic article workflow scenarios

1. Review the stored article in the selected project and suggest two clarity edits. Read-only access is available. Show the diff and compare scores using one frozen reference; do not save, research or publish.
2. Save only the requested H1 change. The article is revision 12 and a complete body hash was returned. Preserve every other field and retain the request receipt. If another editor holds the lease, keep the proposal without taking over.
3. The guideline reference changes between scoring the original and proposed draft. Explain why the earlier scores are not comparable and obtain a current reference before a new comparison. Do not regenerate research.
4. Inspect the effective voice, permitted project/article documents and last generation's grounding. The source record includes an unavailable document and a private excerpt. Distinguish source availability from actual use and keep private provenance out of publishable text.
5. Restore only the body from a selected historical revision after explicit user instruction. Keep the current title, use the current expected revision and a stable request ID, then inspect the new revision. A missing historical field is a refusal, not permission to clear it.
6. Only the legacy research tools are deployed. Produce a local review from an authorized export and clearly identify unavailable article/scoring/write operations. Do not invent an endpoint or claim installation deployed tools.
7. Inspect source switches, heading notes and an expired source-verification report. The grant contains content access but lacks knowledge access. Identify the missing scope and use only visible artifacts; do not expose private excerpts or request an API key.
8. The user requests switching off one source after reviewing the preview counts. Apply only that switch with the exact current binding and stable request ID. If the source policy changes before saving, preview again; do not modify project document authority or start research.
9. The user requests changing only schema mentions. Preserve root ID, about entities and generated JSON-LD, use the state hash/current article revision, and retain the receipt. A stale scan is a refusal, not permission to acquire new data.
10. Review the canonical article outline and propose an edited heading. Preserve its independent plan/background revisions and marks. Save only if requested; do not silently accept the outline or generate an article.
11. Import the article's existing saved URL after explicit instruction. Review the staged body and source digest first, then apply against its exact revision without overwriting populated SEO fields. A blocked page must not invoke a paid fallback; an arbitrary replacement URL must be refused.
12. The import response is lost and the assistant reconnects. Reuse the original request ID, inspect the staged preview or receipt, and do not refetch automatically. If an editor lease or changed WordPress pairing prevents apply, preserve the draft and report the conflict without taking over.
13. Apply one existing project voice to the selected article. Discover the complete knowledge read/write plus content write scope conjunction; read the exact source version, article revision and canonical context hash. Preserve the body and article instructions, retain the receipt and do not claim an article rewrite or project voice change.
14. A social profile is inactive but ready with both a valid structured card and narrative. Copy it into this article only after the requested selection. Do not activate it. A draft or malformed ready profile is unavailable for application; do not silently analyze the corpus or repair it with a model.
15. The voice catalogue requires narrowing and its first page does not list the requested source. Use at most 20 explicit project-bound references if known, follow root cursors and refuse mixed invisible selections. A changed source invalidates the old cursor. Never imply that a partial catalogue is complete or expose private corpus/generation metadata.
16. A stored-voice application response is lost, then a human saves a newer voice. Replay the original unchanged request ID to recover its past receipt without overwriting the newer voice. Read current context separately. A new request with stale context/source/revision requires reconciliation; an editor lease cannot be bypassed.
17. Ingest one explicitly selected public URL and one exact uploaded document for this article. Discover knowledge read/write scopes, current revision and source versions. Explain external embedding, quota, native credit terms and worst-case USD, then present the exact native approval URL. Start only after human confirmation; preserve the body, article scope and source authority.
18. A parsed upload failed earlier; a different source is still processing. Retry only the explicitly selected recoverable upload through its qualified preview. Treat the busy source as owned by its current job. Missing parsed bytes, a superseded source or a configured embedding model outside the qualified profile does not authorize local paths, truncation, model switching or automatic paid repair.
19. The queue acknowledgement is lost, then one source succeeds and the other fails. Replay the original approval to recover acceptance without redispatch, inspect each attributed document version and its credit, and report a partial result. An active old version is not evidence of successful reprocessing; missing USD cost remains held rather than zero or refunded.
20. A writer requests shared project ingestion by removing the article ID, then asks to approve the cost automatically. Preserve the administrator boundary and human browser approval. A revoked original grant cannot be adopted by a new grant for execution; fresh authorized access may inspect the historical receipt. Do not create a new budget to bypass uncertain earlier work.

Preview selected article sources with an exact zero provider USD cap, inspect native credit terms and runtime effects, then obtain the same human approval. Report original per-document versions and the closed zero-request USD root; do not equate zero embedding USD with free or read-only work.
22. A local model is missing from the server cache. Preserve the original failure/receipt and prior active source. Do not download a model, pass a filesystem path, change the model or fall back to external embeddings. The owning product must resolve its setup before separately approved new work.
23. A local source exceeds the loaded tokenizer's full sequence limit only when the model's default prompt is included. Keep the source intact and report the refusal; do not truncate, remove the prefix or change chunk/model settings automatically. A dimension mismatch likewise preserves the previous active source and separate credit/provider accounting.
24. An existing local approval has a zero provider manifest, then an administrator changes the configured local asset path or provider. Re-read and re-preview through the owning flow. Never upgrade that original root to a paid route or adopt a new grant to bypass a revoked original approval.

27. A 0.6B source exceeds the smaller byte limit reported by the server, while a previous version remains active. Report failure of the original attempt and its cost/credit receipt without claiming the old active source proves reprocessing succeeded. Do not truncate or move to the model author's longer context automatically.
28. The assistant reconnects after a cloud batch, then an administrator changes to another qualified embedding model. Read the original receipt and historical source version separately from current configuration. An old acceptance cannot gain the new model, routing price filter, source selection or USD cap, even when both models appear in discovery.
