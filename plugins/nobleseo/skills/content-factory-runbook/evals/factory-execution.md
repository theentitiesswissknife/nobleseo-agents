# Factory execution scenarios

These are authored scenarios, not installed-client or model acceptance evidence.

1. Discover both execution tools and the reported partial native profile. Prepare three explicit current articles with immutable pipeline versions, body/revision fences and per-item/shared work, USD and native-credit limits. Do not promise that every stored pipeline is supported.
2. A selected pipeline requires unqualified fresh analysis, media or source acquisition. Preserve the pre-approval refusal and selection. Do not remove effects silently, substitute another workflow or describe missing engineering as a credential gate.
3. The preview withholds private prompts and source bodies. Explain the version/digest projection and obtain approval for the original selection. Start with only the original project, approval ID and digest; never copy the redacted projection as server execution inputs.
4. Browser approval is pending, expired or belongs to another grant. Preserve the owning refusal. Do not create replacement previews to bypass it or borrow another grant's execution approval.
5. A start response is lost after native admission commits. Repeat only the identical original start or read the original run. An accepted batch with `not_dispatched` items is not evidence that its queue ran; never resend or create a duplicate run automatically.
6. One queue acknowledgement is unknown while another item completes. Keep the same native identities, follow item/action/accounting pages and report both outcomes separately. A stored job is not a heartbeat, and a useful completed artifact is not undone by a late acknowledgement.
7. The user explicitly stops the accepted original batch. Review its exact cancellation snapshot and use the existing stop command once. Preserve known costs, unresolved holds and late results; an identical start still returns the same acceptance without restarting the batch.
8. Sources, template, pipeline checksum, native routing or article revision change after preview. Preserve the stale-input refusal. A new deliberate review may produce another preview; it cannot replace the original identity to recover dispatch uncertainty.
